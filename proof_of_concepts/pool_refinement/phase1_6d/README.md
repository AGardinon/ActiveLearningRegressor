# Phase 1: refinement variants on the 6D Ackley paper setup

Does adaptive refinement let a campaign go beyond the best point of a sparse starting
pool, and which centroid window works best?

Configs come from `benchmarks/6D/GPR/ackley_gpr_40cy_5pts_1stage_3_2/config`:
50k LHS pool, 40 cycles × 5 points, τ = 10, 3 centroids, 250 points per cube, and the
1M-point GT file as validation. Differences from the paper run:

- The seed is set per run (`run.sh` argument), so all variants of a run set share the same
  starting pool (paired comparison). The paper runs used `SEED: null`.
- GPR: `n_restarts_optimizer` 50 instead of 300; config keys translated to the current
  code (`kernel_recipe` → `kernel`, `use_gridsearch` dropped).
- Batch selection: `sampling_method` is set per run: `voronoi` (as in the paper runs) or
  `fps` (argmax of the acquisition, then greedy maximin; the code default).

| Variant | `adaptive_refinement` |
|---|---|
| `norefine` | `null` |
| `history` | `refinement_centroid_window: null` (whole history) |
| `window30` | `refinement_centroid_window: 30` (3τ) |
| `window10` | `refinement_centroid_window: 10` (τ) |
| `history_bestfirst` | `history` + `refinement_centroid_selection: best_first`, `refinement_centroid_top_fraction: 0.2` |
| `window30_bestfirst` | `window30` + the same best-first selection |

```bash
# ./run.sh <variant> [reps=5] [seed=13] [sampling_method=fps]
PY=/path/to/env/bin/python ./run.sh history 5 21 fps   # -> runs/fps_s21/history/, runs/fps_s21/history.log
```

Each run set `runs/<sampling_method>_s<seed>/` holds the variants for one starting pool.

`runs/` is git-ignored. The analysis is in `analysis.ipynb`, generated by `build_notebook.py`
(`python build_notebook.py analysis.ipynb`, then execute it).
